# Security and data boundaries

This development project is for a customer-owned trusted instance, not a public multi-tenant inference service. Use a valid HTTPS endpoint over a private VPN for phones, keep upstream model ports on loopback, and protect the gateway bearer token. Static pages contain no account credentials; authenticated local model APIs are separate. A shared server token is not a per-person identity system.

Provider/OAuth/GitHub/server tokens remain tab-local RAM. Conversations, interview answers and reviewed source-linked facts can optionally be stored in an encrypted local library, separately from the encrypted story board. An unlocked or compromised page can read unlocked data. Clearing browser storage or losing a passphrase can lose access. Memory sharing is off on reload/unlock, profile-bound and separate from local saving. [Storage and recovery boundaries](browser/docs/MEMORY.md). Private chat/history sync is not implemented. Each integration and model disclosure requires its own consent. Broader Google Drive scope is constrained by app policy, not by a folder-scoped Google token. Retrieved instructions cannot grant actions. The web app asks Google for full Drive access and, only when you tick the box, read-only Gmail; this is an intended and disclosed choice for a self-hosted instance using your own Google client ID, and Google will show its unverified-app notice until that client is verified. Google's sign-in script is loaded only when you click Connect and then runs in the same page as the keys and tokens held in that tab. The gateway sends `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `Cross-Origin-Resource-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin-allow-popups`, `nosniff` and `no-store`; if you serve the files from any other host, configure it to send the same headers, because the page's own meta policy cannot forbid framing. As a second line the page refuses to start inside a frame. Each file excerpt shared with a model is shown in its own review, including PEA-created files opened under the Drive source setting; enabled calendar and mail snapshots are covered by one approval per setting and are not re-reviewed when their contents refresh. Local models are reached only through this gateway on the same origin: the browser sends the gateway token, never a provider key, and the gateway forwards no credential to the loopback model server.

Do not put secrets, real transcripts, interview answers, raw provider responses, account identifiers or operator host details in public issues/PRs. Report a vulnerability using this repository's **Security → Report a vulnerability** private reporting feature. Provide a synthetic reproduction with the affected version and no real credentials. Do not test against another person's service or post a working exploit containing their data.

Updates are deliberate: inspect source/release notes, verify independently trusted release signatures, keep data outside program directories, and preserve rollback. No production signing trust is established by this source split. The footer feedback form includes only deliberately entered text and public build identity after review; heuristic credential rejection is not complete redaction.

There is no supported stable release/security-response SLA yet. Maintainers triage development reports; CI checks and scanning are guards rather than proof of complete safety. Model/provider/browser/OS licenses and data-use policies remain separate from this code license.
