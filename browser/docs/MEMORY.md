# Conversations and memory on this browser

Evidence date: 2026-11-08. Development source, verified with synthetic offline tests and an isolated browser preview. No provider, Google account, physical phone or native archive was used for this slice.

## Keep the useful parts

Open **Conversations & memory** above the three workspace tabs. Each Work or Personal profile has its own searchable Chat and Greenhouse conversations. Completed and interrupted threads stay in the current tab by default. Starting a fresh thread keeps the earlier eligible one in this local library. Reconnecting OpenRouter does not erase it.

Choose **Unlock / enable encrypted saving** to retain the library across reloads on this browser/origin. First-time setup includes the current eligible tab-only library and interview answers. After reload, unlock and explicitly choose **Continue**; no conversation is silently restored into a model request. An unlock of an existing saved library replaces current tab-only library contents after review, rather than attempting an unreviewed merge.

Local saving and model sharing are independent. Restoring a conversation clears cached model approval. The next request reviews the provider, privacy/pricing choice, introduction, recalled facts and actual bounded recent-message context. Up to 12 recent completed messages are eligible; interrupted and preview assistant replies are excluded. There is no model call for search, interview, memory selection or encryption.

## Interview and persona

The app-guided form asks the 13 standard interview questions, including names, the assistant's fictional home, family, pets, work, interests, communication and boundaries. It also retains the earlier Web fields, including the owner's separate home city and persona. Every answer is optional, length-limited and profile-bound. Save explicitly. Answers are tab-only unless encrypted saving is enabled. **Share my introduction** in Connections controls whether biographical answers, including the assistant nickname, can reach that profile's model. The projected introduction remains bounded to 3,200 characters, so longer answers may not all reach a request. Persona style has its own visible place in the provider review. Fictional backstories cannot grant tools or external-action permission. The native app's separately protected wellbeing questions are not implemented in Web.

Each interview field has **Read question** using the browser/device voice and **Dictate answer** using the browser's speech recognizer after the speech notice. Recognition may use an online service. Dictation fills only an empty field; it will not replace an existing or concurrently edited answer. Review and save answers manually. Changing steps, closing the interview, changing profiles or hiding the page stops recognition. This is guided dictation, not a continuous spoken interview or background listening.

Saving the expanded interview upgrades an unlocked saved library's plaintext schema to version 2 after an explicit warning. Existing conversations, both profiles and older interview fields remain intact; the owner's previous home city is not reinterpreted as the assistant's. Prepare an encrypted backup before upgrading if you may roll back: older Web versions cannot read schema 2. The encryption envelope stays unchanged, and this does not make Web backups compatible with iOS.

**Move an interview profile** provides a separate Web-to-Web encrypted file containing only the selected Personal or Work interview and persona. It uses a new owner-chosen passphrase, AES-256-GCM and PBKDF2-SHA256 with 310,000 iterations and fresh random salt and nonce. Import authenticates and validates the file and requires the same active profile. By default it fills only empty answers; the owner may instead choose to replace every field, including with blanks. The review shows the current and proposed value for each change before approval. It excludes conversations, the other profile, keys and sharing permissions. A tab-only import disappears on reload unless encrypted saving is enabled. This is a manually transferred snapshot with no automatic synchronization; iOS cannot import it. Keep the export passphrase safe; PEA cannot recover it.

The voice entry in Chat or Greenhouse opens a separate speech screen for that workspace and its current role. Start listening only after reviewing the browser speech notice; the browser may use an online speech provider. Review or edit each transcript before Send. Optional reply playback uses the browser/device voice after a completed response. Voice drafts are kept separately in the current tab for each workspace and cleared on profile change or page disposal; a typed draft is preserved and must be resolved before sending from voice. Greenhouse retains its own model and context. Microphone capture stops when the page is hidden or the screen is closed; this is not continuous, locked-screen or native real-time voice.

## Optional local-time delivery

In **Interview & persona**, enable the local-time switch to vary delivery through quiet hours (midnight–08:00), morning, daytime and evening according to this device's clock. A coarse character hint is shown in the same provider review; no precise time, time zone or location is included. Changing period triggers a new style review on the next request. This is fictional conversational performance, never a claim that the assistant has human feelings or an autonomous off-screen life.

Device **Read reply** uses the chosen browser voice and speed from **Talk with PEA → Choose a voice & speed**. Those two settings are stored locally for this browser and apply to both profiles; they do not travel with private profiles. A missing saved voice falls back to the device default. During quiet hours, local-time delivery asks for seven percent slower speech and a slightly lower pitch; other periods retain ordinary delivery. Browsers/voices may interpret those values differently. The voice-room option can play a completed reply after sending; playback is otherwise explicit. No second model request, timer, new microphone permission or background audio is added.

The switch is per-profile and tab-only, off by default and reset on reload/unlock/Lock. It is not part of the encrypted archive or portable model configuration. Saved persona wording is still independent of this optional delivery cue. Physical phone/headset expression needs owner acceptance.

## Sourced, owner-reviewed memory

Select **Remember from my message**, choose a message in the active Chat or Greenhouse thread, quote its exact words, and write the useful fact. Only a completed owner message can be a source. Review the fact and quote before saving. Assistant replies, retrieved text and model instructions cannot automatically create facts or grant permissions.

Memory sharing starts off and returns to off on reload/unlock. When enabled, local selection proposes at most four facts from the same profile. Relevance matches rank ahead of recency; the last 30 days carry more weight. Ordinary facts leave recall after 90 days. **Durable** facts remain eligible until forgotten, but facts older than 30 days need a topical match. Expiry excludes recall; it does not delete the record. Review exact selected facts in the next provider disclosure. A changed set triggers review again. There is no automatic sharing into Blended or another profile. Turning memory sharing off stops new recall; earlier conversation messages may still contain facts already discussed. Start a fresh thread for a clean message history.

Forget a memory to remove it from future recall. Forgetting its source conversation also removes memories derived from it. These explicit local actions require confirmation and do not delete provider copies, remote files or other browsers' copies. Existing saved source messages are not silently trimmed away to make space.

## Storage and recovery boundaries

The library and story board are separate encrypted stores with separate passphrases. The library uses IndexedDB, AES-256-GCM, PBKDF2-SHA256 with 600,000 iterations, a random 16-byte salt and fresh 12-byte IV per write. A library or board saved by an earlier build at 310,000 iterations is re-keyed with a new salt the next time it is unlocked; after that, an older build of PEA Web reports the record as unrecognized and leaves it untouched. Backups keep the work factor they were made with and are re-keyed on the first unlock after restore. The format label is authenticated. Keys and passphrases stay in page RAM. Only schema-bound transcripts, interview fields and sourced facts enter the encrypted payload; connection keys/tokens, account grants, files and generated images do not.

A library is bounded to 40 conversations, 200 messages per conversation, 150 facts, and about 1.9 MB of encoded plaintext. Messages are limited to 12,000 characters and facts/quotes to 600 each. A message that resembles a credential is replaced by a short placeholder in the saved copy, and a longer message is saved up to the limit; the visible chat is unchanged. Credential-like interview answers or facts are still refused. This is heuristic, not complete secret detection. When the library already holds 40 conversations, a new one stays in the tab with a visible warning until you forget a saved conversation; saving then resumes. Finish or resolve a failed save before replacing a conversation. No automatic oldest-item deletion occurs.

Saves serialize. A revision comparison and write occur in one IndexedDB transaction, so competing tabs cannot silently replace a newer saved revision. On conflict, stop editing, preserve any needed unsaved text, Lock, then unlock the current saved copy. The app does not merge competing revisions. A crash/reload may retain the last completed save; an in-flight final response is not guaranteed to have been saved. Interrupted placeholders are labelled in the saved reader and never replayed as complete model replies.

**Lock** clears unlocked library transcripts, interview fields, memory selections and recalled-context approval from the page. Browser page disposal also clears them. Hiding a tab alone does not lock it: on mobile that is too easy to trigger unintentionally. Stop a request and wait for a local save before locking. A compromised or unlocked page can read unlocked content; encryption at rest does not protect against hostile extensions or malicious same-origin code.

An explicit encrypted library backup can be prepared and downloaded; it contains both Personal and Work libraries and excludes the task board, documents, credentials and sharing permissions. Keep the backup file and its library passphrase safe. On an empty browser, choose the file, enter the passphrase and confirm restore. The file is authenticated and schema-checked before a transactional insert; an existing saved library is never overwritten. Unlock separately to review. This is a point-in-time manual copy, not a merge or automatic synchronization. There is no forgotten-passphrase recovery, native-database import, automatic cross-device history synchronization or cryptographic erasure guarantee. Clearing site data, changing origin or losing the passphrase can lose access. Keep the same trusted HTTPS origin when updating. A program rollback does not roll back IndexedDB. This version reads library schemas 1 and 2; saving an expanded interview upgrades to schema 2. See [co-use](CO-USE.md), [parity](PARITY.md) and [release boundaries](RELEASES.md).
